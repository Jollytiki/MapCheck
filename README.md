# MapCheck

Boundary closure and traverse plotting for land surveys — a browser app that
also reads and writes the `.MAP` files of its 1992 ancestor.

Enter courses as quadrant bearings and distances (or circular curves), and the
app reports the error of closure, the precision ratio, the enclosed area, and
plots the figure. `MAPCHECK.BAS` is the original QuickBASIC program, kept as
the reference for the file format and the survey math.

## Running it

```sh
npm run dev      # serves the current directory on http://localhost:3000
```

There is no build step and no npm dependencies — `package.json` exists only to
provide that command.

## Layout

| Path | What it is |
|---|---|
| `index.html`, `style.css` | The UI, including the print stylesheet for the closure report |
| `app.js` | UI logic: canvas plotting, tables, the plat library, event wiring |
| `crates/mapcheck-core` | The survey math and both file formats, in Rust |
| `crates/mapcheck-wasm` | `wasm-bindgen` shim exposing the core to the browser |
| `wasm-bridge.js` | Points the app at the Rust core when it has been built |
| `MAPCHECK.BAS` | The original 1992 program |

## The Rust core

Everything numeric — bearing conversion and parsing, the circular curve
solver, latitudes and departures, closure, area, and both the `.MAP` and
CSV/text parsers — lives in `crates/mapcheck-core`. It has no dependency on
the browser, so it can be tested directly:

```sh
cargo test
```

Two suites, and they check different things:

- **`tests/parity.rs`** replays fixtures through the Rust port and requires the
  same answers as the JavaScript it replaced. The fixtures are generated by
  running the real `app.js` functions in Node, so this compares against what
  the app actually does:

  ```sh
  node scripts/gen-parity-fixtures.mjs   # regenerate after changing app.js
  ```

- **`tests/survey.rs`** checks the answers are *right*, against geometry that
  can be worked out by hand — a square closes with zero error, four quarter
  curves enclose πr², a curve solves identically from any two of its four
  parameters.

### Building the WebAssembly

One-time setup:

```sh
rustup target add wasm32-unknown-unknown
cargo install wasm-pack
```

(If `rustc` came from Homebrew there is no `rustup` to add targets with —
install one first with `brew install rustup-init`.)

Then:

```sh
./scripts/build-wasm.sh
```

This writes `./pkg`, which `wasm-bridge.js` picks up automatically. Reload the
app and the console reports:

```
MapCheck: calculations running on the Rust/WASM core
```

Until `./pkg` exists the bridge does nothing and the app uses the JavaScript
implementations in `app.js`, which are still there and still work. Both paths
produce the same numbers — that is what `tests/parity.rs` is for.

## File formats

**`.MAP`** (legacy) — one value per line: plat name, course count, then four
lines per course (quadrant, bearing as `DD.MMSS`, hemisphere, distance).
Curves are encoded in the quadrant line as pipe-delimited fields, and the
distance line carries the chord so the 1992 program still plots them.

**CSV / text** — one course per line, `num, bearing, distance`, or
`num, [bearing,] C, <params>` for a curve, where params are prefixed: `R`
radius, `LA`/`RA` arc length and turn direction, `CL`/`CD`/`CH` chord length,
`CB` chord bearing, `D` central angle. A curve with no chord bearing is taken
as tangent to the previous course. `#` and `//` lines are comments. The app's
"Format Help" button documents this too.

Bearings are packed `DD.MMSS` — `35.0020` means 35°00'20", not 35.002° — with
an optional quadrant digit (1=NE, 2=SE, 3=SW, 4=NW), so `135.0020` is
N 35°00'20" E. Separated forms (`45-30-00`, `45 30 00`, `45°30'00"`) are
accepted as well.
